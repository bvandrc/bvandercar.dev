## Project

Blake Vandercar's personal developer site — skills, projects, and a short "about me" — deployed to Cloudflare (Workers static assets, configured in `wrangler.jsonc`) by `.github/workflows/deploy.yml`. Every PR also gets a preview URL, linked from its "View deployment" button by `.github/workflows/preview.yml`. A preview build reuses the data the build fetches from GitHub, npm, and BigQuery (below) from a preview or deploy that fetched it the same UTC day, with the same scripts, rather than fetching it again: the cache key holds the date and a hash of the fetch scripts, `scripts/fetch-downloads/`, and `scripts/shared/`, and `REUSE_FETCHED_DATA=true` makes the fetches keep files already there. While a PR has the `refresh-data` label, its previews fetch fresh data, and adding the label builds one. Both workflows build through `.github/actions/build-site`, which restores and saves that data, and signs in to Google Cloud for BigQuery.

- **Stack**: React 19 + Vite + TypeScript, Tailwind v4, Radix UI primitives (`radix-ui`, wrapped in `src/components/primitives/`), Biome, Vitest + Testing Library for unit/component tests, Playwright for e2e/a11y/Lighthouse.
- **Layout**: `src/` is the app, with unit tests in `__tests__/` folders beside the modules they cover; `playwright/` is the browser suites; `shared/test-support/` holds test helpers either suite can import, like the test-id registry in `selectors.ts` (alias `~/test-support/*`).
- **Base path**: `site.config.ts` holds `BASE_PATH`/`SITE_URL` and is imported by `vite.config.ts` and `playwright.config.ts`. The site is served from the domain root today, but in app code still build asset URLs from `import.meta.env.BASE_URL` (see `Header.tsx`) so they keep working if that ever changes.
- **Security headers**: `SECURITY_HEADERS` in `site.config.ts` is the one source for the CSP and other headers. The build writes it to `dist/_headers` for Cloudflare, and `vite preview` sends it, so CI's ZAP scan, which runs on `main` but not on PRs, checks it. A new third-party script, font, image, frame, or request origin must be added to the CSP there, or the browser blocks it in production.
- **Profile content**: the intro, projects, skills, and "Beyond Code" come from [bvandrc/bvandrc](https://github.com/bvandrc/bvandrc), the source of the GitHub profile README. `pnpm fetch:profile` (`scripts/fetch-profile.ts`, run by Node directly) downloads its `src/content/*.ts` and `src/generated/repo-counts.ts` into `src/generated/profile/`, and the screenshots they reference into `public/project-screenshots/`, all gitignored. `dev`, `build`, `check`, and `test` run it first, through `pnpm fetch:content` (which then runs the two fetches below), since `tsc` and the components import those files. Edit content in bvandrc, never here. Every build reads the bvandrc branch named by `PROFILE_DEV_BRANCH` in that script, `feat/bvandercar-dev-content`, while it exists, so content changes land there rather than on bvandrc's `main`; once it's merged and deleted, builds read `main`. Set `PROFILE_REF` to read another branch or commit for one run. CI also runs weekly, an hour after bvandrc refreshes its counts, so the site redeploys with fresh content.
- **Git activity**: `pnpm fetch:git-activity` (`scripts/fetch-git-activity.ts`) reads each project's `repo` in the fetched projects and writes its commits and PRs per week, through the week under way, from the GitHub API, into `src/generated/repo-activity.ts`, gitignored. Where this site fetched a repo's commits and PRs, or a package's downloads, the counts' glyphs show those totals rather than bvandrc's weekly ones, which are fresher. It needs `GITHUB_TOKEN` and skips every repo without one, so set it locally (e.g. `GITHUB_TOKEN=$(gh auth token) pnpm dev`) to see its totals. CI's browser suites, deploy, and preview builds pass the workflow's own token, which reads public repos; the deploy and preview builds use the `PROJECT_REPOS_TOKEN` secret instead when it's set, a read-only token for every project repo, so the private ones (TaskRankr, SD) are read too. A repo that can't be read is left out with a warning, and its glyphs fall back to bvandrc's counts.
- **Download history**: `pnpm fetch:downloads` (`scripts/fetch-downloads.ts`), which `fetch:content` runs after `fetch:profile`, reads each `npmPackage` and `pypiPackage` in the fetched projects, through `scripts/fetch-downloads/npm.ts` and `pypi.ts`, and writes its weekly downloads since its first publish into `src/generated/package-downloads.ts`, gitignored. The first publish day comes from the npm registry or PyPI's JSON API, which need no credentials. npm's downloads come from its downloads API. PyPI's come from Google BigQuery's public PyPI dataset, queried only when `GOOGLE_APPLICATION_CREDENTIALS` is set: the deploy and preview workflows set it from the `BIGQUERY_CREDENTIALS` secret, a service account key, and other builds, local ones included, skip PyPI. The query is capped at 50 GB billed, and the build logs what it billed. PyPI's daily counts are kept in `.cache/pypi-downloads.json`, gitignored, which the deploy and preview workflows carry between runs in the Actions cache, so a build queries only the days since the last (re-reading the latest 3, which may still be filling in); without it, the build queries the whole history, 180 days a query, since all of it at once bills over the cap, and keeps what it got if one fails. A package that can't be read is left out with a warning rather than failing the build, and its glyph falls back to bvandrc's count.
- **Scripts**: the fetch scripts share paths, like `src/generated/`, and helpers in `scripts/shared/`. Node runs the scripts directly, so they import those by their `.ts` names, which `allowImportingTsExtensions` in `tsconfig.json` lets `tsc` accept.
- **Generated icons**: `favicon.ico` and the touch and manifest PNGs are not committed. `pnpm icons` (`@vite-pwa/assets-generator`, configured in `pwa-assets.config.ts`) writes them into `public/` from `public/favicon.svg`, and `pnpm dev` and `pnpm build` run it first. `.gitignore` keeps them out of git. Their links in `index.html` and entries in `public/site.webmanifest` are written by hand, so keep those in step with the preset's file names. The social preview, `public/preview.png`, is a committed image: update it by hand if the logo or tagline changes.

## Code conventions

Conventions live outside this file, synced from https://github.com/bvandrc/bvandrc-conventions — follow all of them:

- @conventions/typescript.md — language-level TypeScript/JavaScript rules
- @conventions/react.md — component, JSX, and accessibility rules
- @conventions/ts-testing-all.md — testing rules shared by every TypeScript suite: test IDs, naming, assertions
- @conventions/playwright.md — test layout, test IDs, and accessibility scans
- @conventions/ts-unit-testing.md — TypeScript unit test layout, naming, fixtures, and assertions
- @conventions/all.md — practice for every repo: branches, formatting, comments, testing, writing, PR reviews

## Commands

- `pnpm dev` — dev server on port 5000. `pnpm build`, `pnpm preview`.
- `pnpm format` — Biome check/fix. `pnpm check` — the full gate: format plus `tsc` for the app and for `playwright/tsconfig.json`. Run before every commit; it's what CI runs.
- `pnpm test` — Vitest unit tests over `src/`. `pnpm test:watch` to re-run on a change; CI runs `pnpm test:unit`.
- `pnpm preview:ci` — build and serve on port 4173. All three Playwright suites expect this server to already be running.
- `pnpm test:e2e`, `pnpm test:a11y`, `pnpm test:lighthouse` — the three Playwright projects. `pnpm pw:open` for the UI runner.

## Repo conventions

- **Package manager**: pnpm. `npm install` writes a competing `package-lock.json` that CI ignores.
- **package.json**: Linted in CI by `bvandrc/lint-package-json`, which enforces top-level key order, alphabetical `dependencies` and `devDependencies`, and exact-semver `version`. Adding a field in the wrong place, or a dependency out of order, fails the lint job.
- **Convention files**: `conventions/` is synced from https://github.com/bvandrc/bvandrc-conventions and overwritten on every sync. Edit a rule upstream, never in that directory.
